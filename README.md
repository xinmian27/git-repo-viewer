一款面向电脑小白的桌面工具：不用记任何命令行，就能看懂自己电脑上 Git 项目的情况。
纯本地运行、平时只读取信息，**不会改动你的代码**；只有你主动删除 Git 历史并确认后，
才会把该项目的 .git 文件夹移入系统回收站（可还原），项目文件不受影响。

- 面向用户的使用说明（图文步骤）：见《[使用说明.html](使用说明.html)》，双击即可在浏览器打开。
- 本项目以 [MIT 许可证](#许可证)开源，欢迎提 Issue / PR。

## 功能

| 功能 | 说明 |
| --- | --- |
| 扫描仓库 | 选择一个或多个文件夹（按住 Ctrl 多选）或整个磁盘，自动找出里面所有 Git 仓库（可调扫描深度，重叠范围自动去重），以列表展示；首次打开自动扫描常用位置和所有磁盘。扫描中按钮保持可点，随时可重新选择其他位置（自动取消当前扫描），左下角另有「⏹ 停止扫描」随时停下并保留已找到的结果 |
| 基本信息 | 远程仓库地址、当前分支、全部本地分支、提交署名（用户名/邮箱）及其设置来源、最近提交、工作区状态 |
| 提交历史 | 思维导图式版本树：main 主线与各分支分列成泳道、用连线表示父子关系（连线落在节点正中）；点节点看详情（时间、作者、说明、完整版本号），按住空白处或连线拖动平移、滚轮缩放，画布可拖范围随内容自适应；上方可按说明/作者/版本号搜索过滤，并显示「显示 x / 共 N 次」 |
| 版本对比 | 任选两个提交，列出变化的文件（新增/修改/删除/重命名），点开文件逐行看差异（绿增红删），二进制文件友好提示；默认隐藏 `diff --git`/`index`/`---`/`+++` 等原始头部并把 `@@` 换成中文提示，右上角「显示技术细节」可切回 git 原样输出（选择会记住） |
| 删除 | 单个仓库与批量勾选都走同一个确认框，三种选择：「删除 Git 历史」（.git 进回收站可还原，代码保留）、「删除整个文件夹」（进回收站可还原）、「仅从列表移除」（不删任何文件）；每种操作再弹一次确认，删除成功后可直接点「打开回收站看看」 |
| 刷新 | 右侧详情区顶部那一行的「🔄 刷新」（同一行还有项目名、路径、「复制路径」「📂 打开所在文件夹」「🗑 删除」）作用于当前仓库；平时切换仓库显示已缓存内容（秒开），点「刷新」才重新执行 git 命令。快捷键：F5 刷新、Ctrl+F 定位搜索框 |
| 其他 | 仓库收藏列表（📌 置顶 / ↕ 排序 / 管理·批量操作：勾选后「📌 置顶」或「🗑 删除」，删除同样弹三选一确认框）、卡片双击打开所在文件夹与右键菜单（打开/重读/复制路径/置顶/移除）、首次使用自动扫描常用位置和所有固定磁盘、扫描达上限后可一键「继续扫描」（自动加深一层重扫上次位置）、仓库搜索过滤、「⚙ 扫描设置」收纳扫描深度、欢迎页「👀 用示例项目练手」一键生成演示仓库、「📖 使用说明」（三步上手 / 常见名词 / 遇到问题三个标签页）、未装 Git 时的安装引导 |
| 设置 | 工具栏「⚙ 设置」：左栏「通用 / 快捷键 / 关于」。通用页可选外观（跟随系统 / 浅色 / 深色，深色模式有独立配色，含 diff 的深色高亮）和界面语言（简体中文 / 繁體中文 / English，切换即时生效）；快捷键页列出 F5、Ctrl+F、双击、右键等；关于页显示版本号、Git 版本与设置文件位置 |

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（64 位）；源码架构跨平台，macOS 可直接运行（见下文） |
| Git | 需要电脑上已安装 Git 命令行（本软件靠它读取信息） |
| 打包版 | 用 `python build_exe.py` 生成 `dist/Git可视化仓库.exe` 后双击即用，**无需安装 Python**（exe 体积较大，不进版本库） |
| 源码运行 | Python 3.10+（开发时用的是 3.13） |

## 目录结构

```
├── main.py                  # 启动入口（python main.py）
├── build_exe.py             # 一键打包脚本
├── requirements.txt         # 运行依赖（PySide6）
├── requirements-dev.txt     # 开发依赖（+ PyInstaller、Pillow）
├── git_viewer/
│   ├── app.py               # 应用入口与命令行参数
│   ├── git_service.py       # 全部 git 命令封装与解析（纯逻辑，无界面依赖，可跨平台复用）
│   ├── scanner.py           # 目录扫描（找 .git）
│   ├── trash.py             # 把文件/文件夹移入系统回收站（Windows API / macOS 废纸篓）
│   ├── workers.py           # 线程池 + 信号，后台执行不卡界面
│   ├── settings.py          # QSettings 记住上次扫描目录/深度、主题、语言
│   ├── i18n.py              # 界面语言（简体中文 / 繁體中文 / English）
│   ├── utils.py             # 时间格式化、diff 上色等
│   ├── selftest.py          # 自动自检（造演示仓库并验证所有读取功能）
│   └── ui/                  # PySide6 界面（主窗口、三个标签页、删除确认框、设置面板、使用说明、样式）
│       └── version_graph.py # 提交历史的思维导图版本树（泳道布局 + 缩放平移）
├── tools/make_icon.py       # 生成 assets/icon.ico（需要 pillow）
├── assets/                  # 应用图标
└── dist/                    # 打包产物（运行 build_exe.py 后生成，不进版本库）
```

## 源码方式运行

```bash
# 1. 安装依赖（建议在虚拟环境里）
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt

# 2. 启动
.venv\Scripts\python main.py
```

## 自动化自检

不打开窗口，自动造一个演示仓库并逐项验证扫描 / 信息 / 历史 / diff 读取是否正确：

```bash
python main.py --selftest
```

退出码 0 = 全部通过。修改 `git_service.py` / `scanner.py` 后建议先跑一遍。
（删除到回收站是系统级操作，会污染用户回收站，因此不在自检范围内，请手工验证。）

## 打包成免安装 exe

```bash
python build_exe.py
# 产物：dist/Git可视化仓库.exe（单文件，双击即用；该目录不进版本库）
```

图标由 `tools/make_icon.py` 生成（需 pillow，已包含在 requirements-dev 中）。

## 以后要做 macOS 版？

代码在架构上已按跨平台设计：`git_service.py` / `scanner.py` / `utils.py` / `trash.py`
完全不依赖 Windows；Windows 专属逻辑只有三处（`CREATE_NO_WINDOW` 防止闪黑框、
回收站 API、默认字体设置），均已按平台隔离。在 mac 上运行：

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python main.py            # 直接运行
python main.py --selftest # 自检
pyinstaller --noconfirm --clean --windowed --name "Git可视化仓库" \
    --add-data "assets/icon.ico:assets" --icon assets/icon.png main.py   # 打包
```

## 设计说明（给后续维护者）

- **安全边界**：`git_service.py` 只执行只读 git 命令（log/diff/status/branch/config/remote）；
  唯一的写操作是用户主动触发的「删除」：把该项目的 .git 或整个项目文件夹经 `trash.py`
  移入系统回收站（可还原），由用户在确认框中选择。
  演示/自检数据里的 git 写命令仅在临时目录执行。
- **删除**：确认框（`ui/delete_dialog.py`）提供"删除 Git 历史（.git 进回收站）/ 删除整个文件夹
  （进回收站）/ 仅从列表移除"三种选择；删除后作废所有进行中的读取任务（`_seq` 令牌），
  清除该仓库的缓存，并自动选中相邻仓库。
- **信息缓存**：仓库信息按路径缓存在内存里，切换仓库直接秒开；
  只有首次选中或点「刷新」时才执行 git 命令。
- **不卡界面**：所有 git 调用经 `AsyncRunner` 放进线程池，结果用 Qt 信号回主线程；
  每个"任务流"有独立令牌，快速切换仓库时迟到的旧结果会被丢弃。
  注意 `FuncWorker` 必须 `setAutoDelete(False)` 并由 `AsyncRunner` 持有引用，
  否则线程池回收任务后排队中的信号会被丢弃（PySide6 经典坑）。
- **解析健壮性**：git 输出用 `--pretty=format:` + 控制字符分隔（`\x1f`/`\x1e`），
  文件列表用 `-z`（NUL 分隔），避免文件名带空格/引号时解析出错；
  `core.quotepath=false` + `i18n.logoutputencoding=utf-8` 保证中文正常显示。
- **命令行参数**：`--selftest`（自检）、`--make-fixture <dir>`（生成演示数据）、
  `--autotest-demo <dir>`（界面自动演示，供截图/调试）、`--fresh`（跳过启动自动扫描）。
- **主题**：`ui/styles.py` 的 `apply_theme(app, mode)` 同时设 Fusion 风格、显式调色板
  （浅/深两套）与 QSS（`QSS` + 深色时追加 `DARK_QSS`），返回实际生效的 light/dark。
  必须显式给调色板：系统深色模式下 Qt 默认调色板是深色的，只换 QSS 会黑底配黑字。
  diff 的高亮色由 `utils.diff_to_html(text, dark=...)` 决定，深色用另一套低亮度配色。
- **多语言**：`i18n.py` 不在业务代码里逐条包 `tr()`，而是给 Qt 的"写文字入口"打补丁
  （`QLabel.setText`、构造函数的第一个字符串参数、`QTabWidget.addTab`、`QMessageBox.setText`、
  `QMenu.addAction`…），写之前统一过 `translate()`。`retranslate(widget)` 用于已经搭好的
  控件树（对话框弹出前、列表项塞进 QListWidget 时）。繁體中文走字符级转换 + 台湾用词表；
  英文走整串词典 + 若干正则模板，未命中的字符串保留中文（使用说明与安装引导另有整份
  英文正文）。**每个被翻译的控件都把原文存进属性**（`i18nSrcText` 等），`retranslate()`
  永远"从原文重新翻"，所以来回切语言幂等、可逆，不会越切越乱。
- **数据不翻译**：仓库名、分支、作者、邮箱、提交说明、路径一律走 `i18n.set_raw(控件, 文本)`
  或 `badge(..., raw=True)` / `KVRow(..., raw=True)`，繁中模式下不会被字形转换；路径类
  字符串（`D:\...`）在 `translate()` 里另有 `_looks_like_path()` 兜底。
